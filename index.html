Antinuke

Every destructive action has a threshold.

Each of the 28 modules has its own switch, threshold, time window, punishment, incident log and persistent config. Critical modules default to a ban.

Nuke Guard

Counts destructive actions across modules, per executor, before any single module threshold. A mixed burst cannot stay under every limit. At the guard threshold the executor is banned immediately and put on a 24 hour ban-on-sight watch.

  • Ban is the first Discord call, before mitigation or any awaited persistence.
  • If Discord refuses: ban, kick, quarantine, strip dangerous roles, timeout.
  • Bot-add containment, bounded restore concurrency and re-entrant response locks.
  • An optional compromised-account guard removes whitelist immunity from accounts younger than seven days.

How detection works

From audit log entry to ban.

Kurisu reads GUILD_AUDIT_LOG_ENTRY_CREATE. Each entry already carries the executor, target and changes, so there is no polling delay and no guessing from the latest row.

01

Entry arrives

Duplicates by entry ID are dropped. An entry with no executor is ignored, so an arbitrary member is never punished.

02

Exemptions checked

Guild owner, bot owner, Kurisu and the whitelist are skipped. Administrator permission alone gives no immunity.

03

Nuke Guard counts

Warm caches answer without a database read, and destructive actions are counted per executor across all modules.

04

Ban first

The ban goes out before mitigation. Repeat offences within 24 hours escalate to a ban.

05

Nuke watch

A banned or kicked executor is written to a durable 24 hour watch that survives restarts. Any action, message or rejoin while watched is a ban.

06

Mitigate and log

At most three restore tasks run at once, categories first. An incident row and a short log line are written.

Discord limits

Messages in a deleted channel cannot be recovered. Restored channels and roles get new IDs.

Server assets

Icon, banner and vanity URL cannot be restored through the API. Kurisu restores the server name only.

Permissions

Restored roles and overwrites never regain dangerous permissions.

Raid protection

Four levels, one lockdown.

Join velocity and account age move the server between levels. Lockdown can trigger automatically or by hand.

  • Join velocity and minimum account age gates, with a join history log.
  • Verification mode and lockdown use Discord’s verification level, @everyone send permissions and the invite pause.
  • Raid protection never mass-bans. Optional lockdown kicks only accounts younger than the configured age.
  • Ticket channels are excluded from lockdown.
Whitelist

Trust is scoped, never blanket.

Entries can target users or roles, and can be limited to specific protection modules.

trusted_admintrusted_modbypasstrusted bot

Trusted Moderators only bypass message modules unless scopes say otherwise. Administrator permission alone gives no antinuke immunity and no whitelist authority. Owner protections cannot be removed.

/whitelist add level:Trusted Moderator role:@Moderators scopes:channel-create,channel-rename
/whitelist add level:Trusted Moderator user:@member scopes:pings
/whitelist add level:Bypass user:@trusted-admin
/whitelist add level:Trusted Bot user:@logger-bot
Verification and tickets

Front door and help desk.

Verification panel

A public panel with a stable kv:verify button. Every click is re-checked against the database, respects raid lockdown and the minimum account age, has a five-second cooldown per member and writes a member log entry.

/verification panel channel:#verify [role:@Verified]
/verification config
/verification remove

Tickets

Private channels with explicit overwrites for the owner, staff role and bot. Numbers come from an atomic per-guild counter, three open tickets per member by default, and closing needs confirmation. Transcripts are off by default and never written to MongoDB.

/ticket panel channel:#support
/ticket setup [category] [log_channel] [staff_role] [max_open:3]
/ticket close | add | remove | claim | list
Commands

Slash or prefix, same checks.

Text commands use the server prefix (default !) with the same permission, hierarchy and antinuke checks as their slash counterparts.

What Kurisu does

Kurisu is a Discord bot for antinuke protection, raid protection, whitelisting, verification, tickets and moderation. It watches events in the servers where it is installed and responds according to the settings that server chose.

Your responsibilities

You are responsible for how Kurisu is configured in your server, including thresholds, punishments, the whitelist and log channels, and for the people you trust with those settings. Kurisu can only act within the permissions and role position you give it, because Discord’s role hierarchy limits what any bot can do.

Automated actions

Kurisu can ban, kick, time out, quarantine or strip roles from members, and can restore channels and roles, without a person approving each action. Automated systems can make mistakes. Server administrators can review and reverse a punishment with Discord’s tools or Kurisu’s moderation commands.

Discord’s API has limits: deleted messages cannot be recovered, restored channels and roles get new IDs, and the server icon, banner and vanity URL cannot be restored.
